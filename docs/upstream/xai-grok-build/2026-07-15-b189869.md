## Integration decision

**Decision: integrate the complete 27-file delta as one upstream-content commit.**

The replacement contains coherent auth, diagnostics, sandbox, toolset, session-startup, upload, and terminal changes. Splitting the imported tree would weaken provenance and could separate coupled tests from their implementations. No change introduced a generic provider framework, credential store, extension ABI, or other behavior that conflicts with the provider-platform goal.

The fork did **not** reset, rebase, merge, or force-replace its history with the unrelated root. The original publication remains independently reachable and protected.

## Candidate behavior

### Authentication

- External authentication may report an issuer.
- External credentials with the xAI issuer participate in existing first-party xAI session-auth and relay gates.
- Credential-level checks replace one wrapper-level auth-mode check without changing its effective behavior.
- New tests cover issuer parsing, xAI/non-xAI classification, refresh compatibility, and relay eligibility.

This remains xAI-specific compatibility. The issuer string must not become a generic provider trust mechanism.

### Local terminal

- Persistent local shell execution becomes the default.
- Session startup resolves the setting from remote policy, environment, configuration, and default precedence.
- `GROK_PERSISTENT_SHELL=0` or `[toolset.bash] persistent_shell = false` restores isolated local shell behavior.
- Session startup warms the persistent shell when selected.

This is a material runtime change because shell environment, working directory, and functions may persist between tool calls.

### Sandbox diagnostics

- Sandbox-profile conflict detection now returns structured conflict data.
- Pager surfaces conflicts in TUI startup diagnostics.
- Global/user profiles still win on same-name collisions; project profiles remain additive.

The replacement documentation says headless runs also receive stderr warnings, but the imported code has no corresponding headless emitter. That parity gap is tracked as a fork-owned follow-up rather than hidden inside this upstream-content commit.

### Diagnostics and uploads

- Diagnostic upload paths use stable user IDs rather than email addresses.
- Upload and tracing code consumes the credential-level identity consistently.

### Other imported changes

- Session and subagent startup carry the new terminal/backend configuration.
- Toolset resolution gains persistent-shell precedence and tests.
- Authentication documentation explains external issuer behavior.
- Sandbox documentation describes the new warning surface.

## Verification

The integration gate requires:

```sh
cargo fmt --all --check
cargo test -p xai-grok-shell --lib
cargo test -p xai-grok-pager --lib diagnostics::tests

cargo test -p xai-grok-tools persistent_shell
cargo check -p xai-grok-config-types -p xai-grok-sandbox -p xai-grok-tools -p xai-grok-shell -p xai-grok-pager
cargo clippy -p xai-grok-shell -p xai-grok-pager -p xai-grok-sandbox -p xai-grok-tools -- -D warnings
```

- `cargo fmt --all --check` — passed.
- Stable patch-ID comparison — passed; applied content exactly matched the upstream tree delta.

- Focused `xai-grok-tools` persistent-shell tests — passed, **6 passed**.

- `xai-grok-pager` library-test target — blocked by **158** equivalent dependency test-helper visibility errors.

The blocked test targets and lint are recorded as baseline/toolchain issues, not reported as passing. The temporary direct integration was reverted.
